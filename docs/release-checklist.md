# 预览发布与正式发布门槛

## 目前的交付渠道

每次提交构建桌面程序、Android 伴侣、Windows 安装包和便携包。通过流水线后，可从该次 Actions 的 phone-mirror-preview 下载产物和 SHA256SUMS.txt。程序内“版本与下载页面”打开 GitHub Releases 页面；当前不静默下载、不自动安装更新，若尚未创建 Release，该页面可能没有版本。

预览包使用 Android 开发签名，Windows 安装器尚未签名。不能把预览包写成正式发行版。安装/重新安装/启动/卸载测试在临时 CI 环境执行；不会为测试修改用户电脑上的安装和设置。

## 无需手机可执行的检查

- 桌面 CTest、模拟设备的目标绑定/断开/授权/取消测试。
- 画质设置保存与边界检查，Android 画质尺寸计算单元测试。
- 离线演示不产生设备操作；已有本地采集的解码、窗口、停止回归。
- 安装包文件完整性、同版本重装保留设置、卸载保留用户文件、SHA256 校验。
- 以固定尺寸绘制 100%/150%/200% 界面检查图；该检查不能替代实际显示器切换与辅助功能软件验收。

## 外部条件（不属于真机测试，但尚不能自行完成）

- Windows 正式代码签名需要维护者提供证书或签名服务及发布主体信息；不要伪造签名或将开发证书称为可信正式签名。
- Android 正式签名身份需稳定保管与备份；当前缓存开发密钥不能作为正式发布密钥。另需解决正式非调试 APK 无法使用当前 run-as 会话发现方式的问题，正式发布前必须设计并审查替代会话发现机制。
- 项目开源许可证由维护者选择，不自动替维护者授予许可。
- 托管构建服务排队或不可用时，安装包和 Android 变更不得标记验收通过。

## 必须留待手机可用

三档画质实际支持与效果、编码器兼容性、控制/撤权、拔线重连、旋转、持续运行、延迟、手机耗电和发热。各项必须记录真实结果，不用模拟数据替代。
