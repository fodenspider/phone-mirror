# 产品规划与验收标准

更新：2026-10-22。以下是产品要求，优先于开发原型的临时交互方式。

## 产品定位

面向没有技术背景的普通用户，做一个点开即可开始使用的 Windows 手机映射产品。主界面简洁、柔和、安静，保持低占用，不引入浏览器运行时。正式交付是可安装的桌面应用和配套手机应用，脚本与命令行工具只供开发诊断。

“点开即用”不表示绕过手机系统权限：首次安装、USB 调试授权、屏幕共享授权和可选控制权限必须提供逐步引导；后续连接只保留系统要求的必要确认。投屏与控制分别授权，默认只投屏。

## 日常使用流程

1. 打开 Phone Mirror：立即显示连接入口，不弹出终端，不要求配置路径或安装开发工具。
2. 插入手机：自动识别设备；未检测到、未授权、应用未安装等状态分别用日常语言说明，并提供一个明确的下一步。
3. 点击连接：程序处理连接通道，打开手机伴侣应用，引导用户确认共享；等待过程中可取消。
4. 画面出现：优先展示手机画面；工具栏只保留连接/停止、声音、控制、设置等必要操作。未实现的功能不展示可点击的假按钮。
5. 需要控制时，解释用途并引导手机授权。连接断开后立即停止接受新控制，不自动恢复授权。
6. 拔线或停止：回到可理解的连接状态，可以直接重试，不要求重启程序或清理命令。

## 视觉与交互规范

- 暖白/浅灰底色、白色内容区、低饱和绿作为主操作色；正文深灰，次要说明灰色。
- 字体使用系统中文无衬线字体，常规正文约 14–16 px；标题有层级，避免密集小字和大段技术提示。
- 留白充足，按钮形状柔和，边界和阴影克制，不使用高饱和渐变、闪烁状态和无意义动效。
- 一个状态只突出一个主要操作。错误首先说明发生了什么以及下一步，原始诊断信息放到可展开的详情。
- 支持键盘焦点、可读对比度、Windows 缩放与调整窗口大小；不能仅用颜色表达状态。
- 窗口大小改变后画面保持比例，黑边不接受控制。最小尺寸、100%/150%/200% 缩放必须验收。

## 实施顺序

| 阶段 | 交付 | 验收 |
|---|---|---|
| A 当前基础收尾 | 实时画面、鼠标点击/滑动协议、停止与权限边界 | 自动测试通过；控制真机验证待用户提供手机 |
| B 桌面产品入口 | 内置 USB 连接、设备状态、授权等待与取消，简洁柔和的原生窗口 | 不运行脚本即可进入连接流程；无设备/缺少组件也有明确提示 |
| C 完整首次引导 | 手机应用安装/更新、权限步骤、多设备选择、基础画质设置 | 新用户只按界面提示即可完成首次投屏 |
| D 安装与发布 | 安装包、合法分发的运行组件、稳定签名、版本/更新、卸载与本地日志清理 | 干净 Windows 环境无需 CMake、Python、PowerShell 7、Android SDK |
| E 真机验收 | 点击、滑动、滚轮、断线重连、撤销权限、旋转、持续运行与占用测量 | 用户通知手机可用后执行；记录实际结果，不能用模拟测试替代 |

## 完成品门槛

- 普通用户无需输入命令、端口、序列号或令牌；开发工具不出现在默认导航。
- 首次引导可返回、可取消、可重试；错误不要求用户理解 ADB、编码器或协议。
- 投屏、控制、音频等功能明确区分已实现与未来计划，默认隐私设置清晰。
- 使用稳定的正式签名与经过验证的安装包，不把 Actions 调试 APK 当作最终产品。
- 真机完整操作、资源释放、低占用和延迟均有测量或测试记录。当前 151 帧限时接收结果不能作为最终性能指标。
