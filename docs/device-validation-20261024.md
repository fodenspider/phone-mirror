## 短时资源采样

在混合静止画面与交互场景下，对电脑端接收进程进行了 10.04 秒采样：

| 指标 | 采样结果 |
|---|---|
| 单核等效 CPU 使用率 | 6.38% |
| 工作集（working set） | 77.28 MiB |
| 私有内存（private） | 85.98 MiB |

这些数值仅描述该接收进程的短时样本，不是整机总 CPU 使用率、手机耗电或端到端延迟；不能据此推断长时间运行表现。

## 省资源档连接与解码验证

省资源档首次连接及重试均出现 `USB authentication response timeout`，直接最小握手测试也超时，均未开始解码。当时基础 ADB echo 能正常响应，手机会话监听端口和前台服务存在。

随后仅强制停止并重新打开 Phone Mirror，用户重新授权并保持应用在前台，20 秒命令行接收测试通过：

| 指标 | 结果 |
|---|---|
| 输入帧 / 解码帧 | 43 / 43 |
| GPU 表面帧 / CPU 输出帧 | 43 / 0 |
| 分辨率 | 432×960 |
| 接收测试耗时 | 20,049 ms |

测试场景为手机静止应用页，不能将累计帧数除以测试时长作为动态画面的帧率表现。重启应用与保持前台两个因素未隔离，尚不能断言后台切换是认证超时的根因；重连问题仍待定位。

## 清晰档连接与解码验证

清晰档在 Phone Mirror 保持前台、手机页面静止的场景下通过 20 秒命令行接收测试，编码器为 `c2.qti.avc.encoder`：

| 指标 | 结果 |
|---|---|
| 输入帧 / 解码帧 | 46 / 46 |
| GPU 表面帧 / CPU 输出帧 | 46 / 0 |
| 分辨率 | 864×1920 |
| 接收测试耗时 | 20,102 ms |

结束后，`dumpsys` 中没有 CaptureService，有效会话 JSON 不存在。读取不存在的文件时，`adb exec-out` 仍可能返回退出码 0，因此本次以 JSON 有效性判断会话状态，未将退出码误记为文件残留。

省资源档与清晰档的上述结果仅验证静止前台场景下的连接、接收和 GPU 解码，不能替代动态画质、动态帧率或稳定重连验收。

另有桌面端授权等待逻辑修复，用于处理“缺失会话文件但读取退出码为 0”的误判，已在独立构建目录完成 11 项 CTest 回归（全部通过），包括缺失文件仍返回退出码 0 的模拟授权等待场景；它与此前的认证响应超时不是同一问题。另修复了桌面窗口标题的默认初始化。
